# Работа с infra и серверами

В Git хранится общий движок infra. Личный реестр серверов, включая серверы без infra,
доступен локально через `.ops` и исключён из Git и раскатки. Устройство — `docs/operations.md`.

Перед задачей на реальном сервере:

1. Прочитай `.ops/README.md`, затем `.ops/servers.yml` и карточку нужного сервера.
   `.ops` может быть символической ссылкой. Если реестра нет, используй адрес из поручения
   и доступные настройки SSH; не восстанавливай личный реестр из догадок.
2. Сопоставь имя, алиасы, IP и описание. При неоднозначности уточни цель до изменений.
   Проверь текущий доступ и состояние: запись в реестре — последнее наблюдение.
   Ошибка SSH не меняет известный способ управления. Если нет свежего доступа,
   используй сохранённые конфигурации и историю как источник прежнего состояния,
   укажи источник отдельно от текущей проверки доступности.
3. Используй способ управления из карточки. На сервере с infra актуальные настройки —
   `/etc/infra/server.yml` и `/etc/infra/secrets.yml`; применяй штатные команды движка.
   На остальных серверах следуй их способу обслуживания; установка infra — отдельная задача.
4. Выполняй поручение пользователя без повторных согласований уже разрешённых действий.
   Наличие доступа само по себе не поручает обновлять, перезапускать или перенастраивать сервер.
5. После работы проверь результат, обнови факты и время проверки в реестре, допиши
   `.ops/journal/YYYY-MM.md`: задача, изменения, проверка, результат и откат при необходимости.
   При неудаче запиши наблюдаемую ошибку, не выдавая предположение о причине за факт.

Секреты читай только по необходимости для текущей операции. Не выводи значения в чат,
журналы и команды с видимыми аргументами. Не загружай `.env` через `source` или `eval`:
читай его как данные. Не копируй закрытые SSH-ключи из `~/.ssh` в проект.
Личные сведения остаются в `.ops`; в отслеживаемые файлы добавляй только общие инструкции
и вымышленные примеры. Не добавляй `.ops` в Git принудительно и не передавай её на серверы.

Для изменений движка сначала читай соответствующие разделы `README.md`, `ADMIN.md`
и `DECISIONS.md`. Проверки — `make check`; раскатка и сценарии на VDS выполняются только
в рамках поручения на такую проверку. Для правки локального реестра достаточно проверить
формат YAML, ссылки на карточки, права доступа и исключение `.ops` из Git и rsync.
